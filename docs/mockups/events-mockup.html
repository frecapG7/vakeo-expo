F, G, H, I — États vides & participation (pattern A/B)

Règle : un vide n'est jamais un trou, c'est un appel à l'action discret — chip pointillée « Définir la date », lien « Ajouter », avatar fantôme « + ». Les events fraîchement créés via le flow tombent exactement dans ces états (date optionnelle, participants optionnels). Owners : « Créé par X » dans le héro + badge étoile ambre sur l'avatar du responsable + « (orga) » dans le décompte — display-only tant que le backend ne définit pas de permissions owner-seulement.

L'étoile désigne les responsables de l'organisation. Au moins un responsable est requis.

Règles d'interaction

Tap ligne → toggle participation
Tap étoile → toggle orga (participant uniquement)
Créateur → owner par défaut, étoile posée
Décocher un owner → retire aussi son étoile
Dernière étoile → impossible à retirer (toast d'erreur)
Body PUT → attendees + owners (owners toujours participants, validé côté front)
Flow création → même composant, créateur auto-owner

Notes d'implémentation RN : la pill PARTICIPER chevauchante = marginTop: -21 sur le bouton dans le flux ; la chip date du héro reprend GlassSurface clear + tint ambre (pattern chip date home, avec blurTarget = le héro sur Android) ; la grille de types utilise les illustrations assets/icons/*_event_icon.png existantes en EventIcon size="sm". Les compteurs « 6 articles / 12 messages » sur les tuiles d'actions nécessitent goodsCount (déjà dans le modèle Event) et un compteur de messages par event — à confirmer si l'API le renvoie, sinon on masque le sous-texte.
