La timeline existante devient jauge : nœud plein + coche quand l'étape a adresse et hébergement, nœud creux tant qu'il manque quelque chose. La bannière finale n'apparaît qu'une fois, à la complétion du dernier segment.

Mapping données (tout existe déjà)

Ring dashboard : trip.startDate (dates), stops[].location/accommodation (étapes), polls.pendingPollsCount / openPollsCount (sondages), goods.total / missing (liste). Score = moyenne pondérée, calculée côté front. Pondérations à régler ensemble (ex. dates 25%, étapes 30%, sondages 25%, liste 20%).
J-x : dayjs().diff(trip.startDate) — masqué si pas de dates.
Badges : purs, recalculés front à chaque dashboard (dates posées / étapes complètes / 100% voté / liste finie / départ passé…).
Prochaine action : priorité simple — sondages en attente > étape incomplète > items manquants > dates absentes ; CTA direct vers l'écran.
Étapes : complétion = location && accommodation, déjà sur la carte actuelle (les plus.circle).

Garde-fous

Pas de dark pattern : le score informe (chaque barre est tappable vers l'écran réel), aucun streak ni notification. Les états « complets » restent discrets (chip ambre, pas de confetti permanent). Le badge verrouillé s'affiche en opacité réduite, il indique quoi faire sans frustrer.
