## Liquid Glass / GlassSurface (posé le 2026-09-27)

- `components/ui/GlassSurface.tsx` — surface translucide **3-tier** : `GlassView` natif si iOS 26 + `isLiquidGlassAvailable()` → `BlurView` (iOS < 26, Android 12+ via `blurMethod="dimezisBlurViewSdk31Plus"`) → `View` translucide.
- `tintColor` est respecté sur **tous les tiers** (calque semi-transparent 90% dans les fallbacks) — indispensable pour la lisibilité des chips sur Android.
- `GlassSheetBackground` : fond de BottomSheet en verre, `tintColor` **thématique** (brume en clair, encre nuit en sombre via `useColorScheme`), intensité 70 — sans ce calque, le sheet est transparent sur les fallbacks. Retire le `backgroundColor` plein du style par défaut (sinon il masque le verre).
- Règles : **jamais d'opacité < 1 sur un GlassView ou son parent** (le verre ne rend plus) ; animer via `glassEffectStyle` en config `{ style, animate }`. Piège RN : `flexShrink` vaut 0 par défaut — pour contraindre une surface dans une ligne, il faut `alignSelf: "flex-start"` + `maxWidth: "100%"` sur la surface (le `items-start` sur le parent casse la contrainte de largeur).
- Validation device Android : OK (build compile, chip/sheet/fallbacks vérifiés visuellement, 2026-09-27).
- **expo-blur 57 (2026-09-29)** : nouvelle API Android — le blur exige un `blurTarget` (ref d'un `<BlurTargetView>` enveloppant le contenu à flouter), sinon fallback `none` + warning. GlassSurface expose donc un prop `blurTarget`. **Usages câblés (3)** : chip date de la home (cible = image de sa carte), sheet « Ajouter » de la home (cible = la liste, `SheetBackground` mémorisé par `useCallback`), **sheet éditeur d'étapes (2026-10-06, cible = la liste des étapes)**. Patron : `BlurTargetView ref={...} style={{ flex: 1 }}` autour du contenu, `SheetBackground = useCallback((props) => <GlassSheetBackground {...props} blurTarget={ref} />, [ref])`.
- Le vrai Liquid Glass (iOS 26) reste **non validé** — pas de Mac/iOS dispo. Idem le scroll-edge iOS 26 (large title sur verre). Options : iPhone + EAS Build (compte payant) ou cloud Mac.

## Bug encodedId (08/10) — RÉSOLU, fix backend livrée

Diagnostic posé pendant la validation device du join (trip public) : join OK puis **422 sur `POST /v3/trips/batch`**, seat en cours jamais reconnu (« déjà membre » jamais détecté).

- **Cause (côté back)** : l'encodedId était **généré à chaque appel sans persistance** → deux appels successifs sur le même trip renvoient deux ids différents. Côté front l'encodedId est (1) la clé MMKV `trips.<encodedId>`, (2) la clé de navigation `/[id]`, (3) le seul rattachement du seat en cours (`storage.getString("trips." + resolved.encodedId)`). Un id instable casse les trois : rejoin en boucle (plusieurs seats claimés serveur, plusieurs clés MMKV), et toutes les requêtes ultérieures qui partent avec un ancien id sont indéchiffrables côté back → 422 fail-closed du batch.
- **Fix livrée le 08/10** : les encodedIds sont **persistés côté serveur** (contrat : id stable par trip pour toujours). C'est ce qui permet au design storage front (clé = encodedId opaque) de tenir.
- **Nettoyage du tel de dev (08/10, fait)** : purge chirurgicale d'abord (one-off `__DEV__` dans `app/index.tsx` pour identifier puis supprimer l'entrée morte `trips.9eD5wNoj…` — **one-off retiré ensuite, `app/index.tsx` revenu à son état initial**), puis **wipe complet de l'instance MMKV** (option A : les 3 autres entrées dataient aussi de l'ère pré-fix, ids morts) : `adb shell am force-stop com.frecapg7.vakeoexpo` + `run-as … rm files/mmkv/vakeo-storage files/mmkv/vakeo-storage.crc`. Les seats fantômes côté serveur sont des données de test — pas de nettoyage back requis.
- **Prod : la bascule v3 roulera seule.** Utilisateur v1 → migrate au premier lancement → `POST /v3/migrate` renvoie un encodedId **persisté** → re-key MMKV → toutes les requêtes suivantes stables. La population touchée par la fenêtre pré-fix se limitait aux tels de dev.
- **Invariants à faire confirmer noir sur blanc au back** (c'est l'assurance qui empêche le bug de revenir) : (1) **toutes les surfaces qui mintent un encodedId persistent désormais** — migrate, création `POST /v3/trips`, share/resolve (le JWT embarque l'id persisté, pas un neuf), batch renvoie le même id ; (2) **aucun endpoint ne re-minte jamais l'encodedId d'un trip existant**, y compris le rotate-token de la Phase 6 (il fait tourner les seat tokens, jamais les ids).
- **Garde-fou proposé (option B, non implémentée)** : le batch pourrait résoudre un item **par son `token`** quand l'id est inconnu (les seat tokens sont persistés, eux) → le front re-keyerait sa clé MMKV depuis l'encodedId de la réponse. À poser au back comme voie de récupération générique.

## Conventions à respecter

- Le projet est écrit à la main par l'utilisateur, avec des zones de qualité inégale assumées. Amélioration **opportuniste** : on nettoie ce qu'on touche de toute façon, pas de grand refacto à part. Signaler le douteux, corriger dans le périmètre de la tâche. **Pas de code sans validation utilisateur** quand il y a un doute de périmètre.
- **Styles** : motif composant → variante de composant (pattern `Button.tsx`) ; chaîne réutilisable → `@utility` + `@apply` dans `global.css` ; nouvelles couleurs → tokens `@theme` dans `global.css` ; surfaces translucides → `GlassSurface`. `text-md` interdit.
- Les fichiers agent (`NOTES-agent.md`, `docs/*-agent.md`, `docs/plan-*.md`) sont en français.
- Couche API : hooks React Query dans `hooks/api/`, client axios dans `lib/axios.js`. **Auth v3 : le header `x-user-token` est injecté par l'interceptor, qui déduit le trip de l'URL (`/trips/<id>/…`) et lit le token dans MMKV au moment de chaque requête.** `v3Path` (`lib/api-v3.ts`) sur chaque endpoint migré ; plus de header posé à la main. leave/rotate-token n'auront qu'à écrire le stockage. **Cache mutations (07/10, review PR)** : `setQueryData` du détail d'abord, puis `await invalidateQueries` — `usePolls` aligné sur ce pattern partout (post/put/vote/unvote) ; vote/unvote invalident aussi `["trips", id, "stops"]` (polls embarqués `hasSelected` → badge sondages de la page étapes).
- Stockage : MMKV, clés `trips.<encodedId>`, shape lean `StorageTrip` = `{ _id, user?, token? }` dans `hooks/storage/useStorageTrips.ts`. Instance `vakeo-storage` (`storage/index.tsx`) — ne contient que `trips.*` et `migration`.
- **Écrans : conteneur standard `Screen`** (`components/ui/Screen.tsx`) — SafeAreaView edges gauche/droite/bas sous header natif. **Écrans poussés full-bleed (liste scrollable + FAB) : `edges={[]}` + padding du contenu porteur du clearance (pattern goods/location)** ; le FAB passe `bottom: insets.bottom + 40`.
- **Tuiles sélectionnables (a11y)** : choix unique → `accessibilityRole="button"` + `accessibilityState.selected` (tuiles avatar) ; toggle multiple → `"checkbox"` + `checked` (restrictions). Conventions posées en review PR le 07/10 — à propager sur les prochaines tuiles.
- **FormLink (08/10)** : le `pattern` du caller est la source de vérité — `handlePaste` s'y fie pour valider un lien collé (http(s) ET schemes custom) ; un nouveau formulaire de lien passe son pattern, jamais une règle http codée en dur.
- Ne jamais éditer un fichier sans l'avoir lu au préalable dans la session.
- **Trip actif : `useTrip()`** depuis `@/context/TripContext` — hook dédié, throw si utilisé hors layout `[id]` ; ne plus faire de `useGetTrip` parallèle dans les écrans sous layout `[id]` (double fetch, remplacé partout où touché).
- Outil : le repo est en **CRLF** — l'outil `edit` échoue sur les fichiers non réécrits ce session ; préférer `write_file` complet (sûr pour l'UTF-8) ou PowerShell `[System.IO.File]::ReadAllText/WriteAllText`. **NB 2026-10-06** : (1) l'affichage console de bash est lossy sur les accents mais les octets sur disque sont propres (vérifié au niveau bytes — ne pas « réparer » sur foi de l'affichage) ; (2) les remplacements multi-lignes doivent reprendre l'indentation exacte du fichier — sinon l'ancre échoue (dump la zone avant) ; (3) éviter les concaténations de chaînes dans les littéraux `@()` imbriqués de PowerShell (évaluation erratique) — précalculer les motifs en variables. **NB 08/10** : `Get-ChildItem -Recurse` depuis la racine timeout (node_modules) — toujours cibler des sous-dossiers ; `npx` très lent à froid, passer par `node_modules\.bin` directement.
